# Standalone A4S dependency audit

The extraction base is `a285fcf4453d38feff9c80b53bf57c8207d30930` from the sibling GitHub checkout's recorded `origin/main`. It contains PR #3 for missing curves, #4 for A4S realization correctness, #5 for native slot reuse, #6 for histogram lifecycle, and #7, #8, #10, and #11 for SHARDS. The older SSH checkout's main is `b9f932636b1280c1c286ef6b8780bcbbcb45059c`. A read-only remote check confirmed `a285fcf4` as GitHub main.

The local online-penalty line at `87f26eae8abbe0b68cd4a9bbc754dd420e475519` diverged from `b9f93263` and has additional unpublished working-tree changes. A dry merge with the selected main reports conflicts in MRC handling, the metric/Justin transports, RocksDB profiling, the scaling executor and native realization. The selected base preserves reviewed SHARDS and memory-only realization. Porting the online branch requires its own integration and behavioral verification. The sibling native slot preallocation branch at `de1e06551d976e8f98290213f444137dabf0d829` adds separate experimental changes.

| Component | Baseline dependency and boundary |
| --- | --- |
| `A4S` | Operator uses Flink topology, job vertex IDs, scaling summaries and configuration. Its bounded selection over a memory–parallelism frontier is pure. |
| `MemoryParallelismCurve` | The fixed hit/miss cost equation and inversion can run on normalized inputs. Baseline uses the total vertex curve and feeds the resulting MiB to a legacy managed-memory reservation. This is distinct from actual block-cache capacity. |
| `flink-a4s` `MissRateCurve`, `StackDistanceHistogram` | Inversion and projection are mathematical. The publication classes carry Flink shaded Jackson wire annotations and legacy/SHARDS histogram semantics. Runtime aggregation stays at the existing endpoint for the initial integration. |
| `ScalingMetricEvaluator`, `RestApiMetricsCollector`, `AutoScalerOptions` | Flink-specific DS2 demand, restart estimates, partition bounds, configuration, REST collection and telemetry history. The adapter supplies the existing demand and normalized MRC to the core. |
| `A4SHistogramMetricCodec`, `A4SAggregatingVertexMetricsHandler`, `A4SAggregatedMetricsResponseBody` | Flink task metrics, REST and telemetry aggregation. Keep roster, missing-curve, and SHARDS handling in the runtime. |
| `ScalingExecutor`, `NativeFlinkService`, `AdaptiveScheduler` | Stateful transition authority stays with the operator and scheduler. The executor reads applied profiles through opt-in Justin GET. Native realization writes complete Justin vertex requirements and uses the existing scheduler, checkpoint and recovery paths. |
| `RocksDBNativeMetricMonitor`, FRocksDB QuickMRC and SHARDS | Native cache-local sampling and JNI. `cache/shards_mrc_estimator.*` depends on Slice, RocksDB hash and portability mutex. Offline trace implementation lives in `trace_replay/shards_mrc.*`. Only aggregates travel upstream. |
| Online/calibrated and learned models | The reviewed base has the fixed latency model. The divergent online branch includes window alignment, fit qualification and shadow projection. No trained throughput model or calibrated migration model was identified on this base. |
